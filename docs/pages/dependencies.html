DOM Hydration & Mount

@keshavsoft/json-to-dom

package.json: ^42.1.5
Live Page / Docs GitHub Repo npm Package
The Story: Why It Exists

Building DOM elements using innerHTML += `...` creates severe security vulnerabilities (XSS), destroys event listeners, and causes frequent layout thrashing. Alternatively, writing 50 lines of imperative document.createElement, setAttribute, and appendChild leads to unmaintainable spaghetti code.

@keshavsoft/json-to-dom was extracted to be the sole consumer of AST specifications. It takes an immutable JSON description (e.g. { tagName: "table", attributes: {...}, children: [...] }) and cleanly materializes real browser DOM elements using high-performance native APIs in a single batch pass. 

import jsonToDom from "@keshavsoft/json-to-dom";

// Materializes JSON AST into live DOM nodes without innerHTML risks
const dom = jsonToDom({
  jsonSpec: tableAST,
  targetHtmlId: "dom-render-container",
  appendPosition: "replace"
});
Container Event Delegation

json-renderers-build-table-events

package.json: ^1.2.2
Live Page / Docs GitHub Repo npm Package
The Story: Why It Exists

In traditional component libraries, event handlers like onSearch or onRowClick are directly bound to table elements during render time. When a user filters a search input, re-rendering the table destroys the input element, instantly blurring the focus and resetting the cursor!

json-renderers-build-table-events solves this by pulling all event delegation into a decoupled, top-level listener on the container. Driven by declarative bindings.json and DOM traversal rules, it intercepts events as they bubble up. When filtering, it repaints only the inner tbody rows, leaving the search input, headers, and keyboard focus 100% undisturbed. 

import { hookTableEvents } from "json-renderers-build-table-events";

hookTableEvents({
  container: "table-container",
  dataset: records,
  columns: columns,
  onSearch: (query, filtered) => console.log("Filtering:", query),
  onRowClick: (record) => console.log("Selected row:", record),
  onSave: (newRecord) => console.log("Footer save:", newRecord)
});
Defensive Schema Validation

json-renderers-guard

package.json: ^1.5.3
Live Page / Docs GitHub Repo npm Package
The Story: Why It Exists

Silent runtime failures are the enemy of resilient front-end apps. Passing an undefined data object, missing column definitions, or an empty container ID deep inside an AST pipeline causes cryptic errors like Cannot read properties of undefined (reading 'map').

json-renderers-guard provides a fast, zero-dependency contract validation checkpoint. It validates incoming parameters at the gate and throws human-readable, actionable errors before any instruction dispatch begins. 

import guardFunc from "json-renderers-guard";

// Validates container ID, columns array, and dataset structure
guardFunc({
  targetHtmlId: "dom-render-container",
  columns: columns,
  data: dataset
});
Universal Instruction Runner

json-renderers-run-instructions

package.json: ^1.9.4
Live Page / Docs GitHub Repo npm Package
The Story: Why It Exists

Transforming raw datasets into component structures requires multidimensional traversals: 1D (mapping columns into table header cells) and 2D (iterating rows over columns to populate table body cells). Originally, this iteration logic was hardcoded inside the table builder.

json-renderers-run-instructions extracted this transformation mechanism into a pure, deterministic engine. It knows nothing about HTML, DOM, or CSS. It reads declarative instruction sets (single, rowOnColumn, columnOnRow) and executes JSONPath injections into template blueprints with extreme speed. 

import runInstructions from "json-renderers-run-instructions";

// Pure AST transformation: Zero DOM, 100% data transformation
const spec = runInstructions({
  instructionMainKey: "table",
  instructionSubKey: "withFooter",
  data: { data: dataset, columns: columns },
  options: { showSerial: true }
});
Declarative Schema Repository

spec-repo

package.json: ^1.17.2
Live Page / Docs GitHub Repo npm Package
The Story: Why It Exists

Hardcoding HTML templates or JSON schema blueprints inside JavaScript libraries prevents reusable UI design systems and creates version fragmentation.

spec-repo serves as the centralized, immutable repository of component definitions, base templates, tags, and instruction recipes. It contains recipes for tables (simple, withFooter, headerOnly, bodyOnly, footerOnly), forms, and lists, allowing components to evolve their markup independently from their runtime engines. 

import { definitions, spec, instructions } from "spec-repo";

// Access centralized table definitions and base AST templates
console.log(definitions.table); 
// { simple: {...}, withFooter: {...}, headerOnly: {...}, bodyOnly: {...}, footerOnly: {...} }
