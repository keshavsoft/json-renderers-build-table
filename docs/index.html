The Paradigm Shift

Why This Library Exists

HTML tables are notoriously cumbersome when built dynamically in JavaScript. Here is how declarative stamping solves it.

The Fragile Imperative Way
  • Scattered DOM calls: Endless document.createElement("td"), innerHTML strings, and append loops.
  • Multi-region touch points: Adding or changing 1 column requires editing headers, body loops, footer totals, and colgroups.
  • Impossible to test cleanly: Requires JSDOM or full browser environments just to verify cell structure.
  • Tight coupling: Logic, templates, and DOM execution are entangled together.
// Imperative DOM mess const tr = document.createElement("tr"); data.forEach(row => { const td = document.createElement("td"); td.textContent = row.itemName; tr.appendChild(td); }); table.querySelector("tbody").appendChild(tr);
The Declarative Specification Way
  • Single source of truth: 1 column config defines width, header, body cell template, and footer automatically.
  • Pure JSON in, Pure JSON out: The builder is a pure function that returns a DOM specification object.
  • Never touches the DOM: Testable anywhere (Node.js, Workers, CI) with plain object comparisons.
  • Separation of concerns: The builder stamps specs; @keshavsoft/json-to-dom renders them.
// Declarative pure JSON builder import { simple } from "json-renderers-build-table"; const spec = simple({ columns, data, options: { showSerial: true } }); // Pass plain JSON tree to renderer window.ks.jsonToDom.appendToDom({ jsonSpec: spec, targetHtmlId: "container" });

Behind The Scenes

The 3-Layer Instruction Architecture

Every table build runs through a declarative instruction engine over an immutable specification template.

1
The Shared Registry

Combines your raw data (columns & rows), the empty table skeleton base with data-role anchors, and pre-built templates in spec.json.

registry = { data: { columns, data }, base: skeletonTable, spec: namedTemplates, ...options };
2
Declarative Instructions

JSON instructions map source data paths to target destination anchors without imperative loops:

{ "narration": "Build colgroup widths", "sourcePath": ["columns"], "templateKey": "buildColGroup", "destinationPath": "table-colgroup", "func": "fromCollection" }
3
writePath Anchoring

Tree writers find target elements using semantic data-role anchors (e.g. table-body, table-header-row) and execute operations cleanly.

// Target anchor resolution base.querySelector( '[data-role="table-body"]' ).children.push(...rows);
Modular API

Pick the Right Builder for Your Flow

Whether you need a complete table or just need to refresh dynamic rows via AJAX, there is a dedicated builder.

Standard
simple()

Generates a full table containing colgroup, thead, and tbody.

  • General purpose data tables
  • Read-only or report views
  • Supports serial & options
Full-Featured
withFooter()

Generates complete table with colgroup, thead, tbody, and tfoot.

  • Totals & calculations footer
  • Inline new-entry input cells
  • Editable grid interfaces
Dynamic
bodyOnly()

Generates only the tbody rows specification.

  • AJAX / fetch data refreshes
  • Avoids re-rendering headers
  • High-frequency updates
Summary
footerOnly()

Generates only the tfoot row specification.

  • Dynamic summary updates
  • Separate footer calculations
  • Isolated input bars

Install from npm for modern bundling workflows, or drop in via CDN ES modules directly in the browser.

# Install via npm npm install json-renderers-build-table # Or using pnpm pnpm add json-renderers-build-table
